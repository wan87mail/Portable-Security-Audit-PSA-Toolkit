Description

[DEMO DATA - not from a real system] The SMB 1.0 server component is enabled. SMBv1 lacks modern integrity and encryption protections and is deprecated by Microsoft.

Potential impact

SMBv1 has been used by wormable malware (e.g. WannaCry via MS17-010). If a related patch is missing, remote code execution may be possible.

Why this severity

High: configuration directly observed and network-exposed; not Critical because MS17-010 patch status is assessed separately.

Recommended remediation

Disable SMBv1 after confirming no legacy clients depend on it: Disable-WindowsOptionalFeature -Online -FeatureName SMB1Protocol (run by an administrator during a change window, not by this tool).

How to verify the fix

Get-SmbServerConfiguration | Select EnableSMB1Protocol should return False.

References

  • CVE: CVE-2017-0144 (CVSS v3.1 8.1, NVD (sample reference))
  • BASELINE: MS-SecBaseline: Configure SMB v1 server = Disabled (Microsoft Security Baseline)

CheckDEMO-LNX-SSH-001
Fingerprint32ad2829caa2d0df

Description

[DEMO DATA - not from a real system] The effective sshd configuration has PermitRootLogin yes and PasswordAuthentication yes.

Potential impact

Attackers can target the root account directly with password guessing; a successful guess grants full control and bypasses per-user accountability.

Why this severity

High: directly observed, remotely reachable, targets the most privileged account.

Recommended remediation

Set 'PermitRootLogin no' (or 'prohibit-password') and 'PasswordAuthentication no' in /etc/ssh/sshd_config.d/, then reload sshd.

How to verify the fix

sudo sshd -T | grep -Ei 'permitrootlogin|passwordauthentication'

References

  • BASELINE: CIS Ubuntu Linux: Ensure sshd PermitRootLogin is disabled (CIS Benchmark (title only; content licensed separately))

CheckDEMO-WIN-RDP-001
Fingerprint281ed34f9a1bd878

Description

[DEMO DATA - not from a real system] RDP is enabled and UserAuthentication = 0, so the logon screen is presented before the client authenticates.

Potential impact

Unauthenticated users can reach the logon screen, increasing exposure to brute-force attempts and pre-authentication vulnerabilities.

Why this severity

Medium: weakens an authentication control on a remote service; not High because RDP exposure is limited to the internal network.

Recommended remediation

Require NLA via Group Policy: Computer Configuration > Administrative Templates > Windows Components > Remote Desktop Services > Security > 'Require user authentication for remote connections by using NLA' = Enabled.

How to verify the fix

reg query "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" /v UserAuthentication should show 0x1.

References

  • CWE: CWE-287 (MITRE CWE: Improper Authentication)
